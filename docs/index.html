Open source · self-hosted · any AI model

Run an AI assistant business from one server.

cob-rag-engine is an engine for AI chat assistants. Each business you serve gets an assistant that answers from its own documents and website, on its website and on WhatsApp, in English, Hindi and Hinglish. You run the server, you set the prices, and you keep the margin.

Two kinds of people run it.

Most run it as a business: they sell assistants to clinics, shops, coaching classes and service firms. Others use it as the knowledge layer under their own product or their AI agents.

Founders and agencies

Everything between "a business signs up" and "the business pays you" is already built. You choose the plans and the prices.

From install to invoice, in six stages.

The example is a pathology lab in Pune. Every stage below is in the engine today.

  1. Step 1 of 6 · Install

    One command on a fresh server.

    The installer checks the server, installs Docker, asks for your web address and your e-mail, and starts everything behind HTTPS on that one address.

    • Ubuntu 22.04 or 24.04, or Debian 12.
    • Nightly backups, upgrades with a backup first, and one command to go back.
    • Files stay on your server's disk. S3 is an option.
    Terminal · on the server
    git clone https://github.com/callobuzz/cob-rag-engine.git
sudo bash cob-rag-engine/deploy/install.sh

  2. Step 2 of 6 · Add a business

    The business signs up and sets up its assistant.

    A business picks a plan, verifies its e-mail and lands on a short first‑run setup. Its dashboard shows seven plain menu items; you decide per plan what else it sees.

    • Owners and members, invitations by e-mail, an audit log.
    • You approve sign-ups, or let them in at once.
    • Owners can move between plans themselves.

  3. Step 3 of 6 · Learn

    It reads their documents and their website.

    PDF, Word, Excel, PowerPoint, scans and audio go in. The engine splits them along their own headings, so every passage knows which section it came from.

    • OCR for scans, including Hindi.
    • It reads the business's website and checks it again for changes.
    • Duplicates are skipped; a new upload of a file becomes a new version.

  4. Step 4 of 6 · Answer

    It answers, and it checks its own facts.

    Before a sentence reaches the visitor, every price, date, number, phone, link and name in it must appear in a cited passage. When the documents do not say, the assistant says so and offers a person.

    • On the website widget and on the business's WhatsApp number.
    • English, Hindi and Hinglish, with a model per language.
    • Greetings and small talk answered without a model call.
    See the example

    Reports are ready within 2 hours.

    Removed: no cited passage says "2 hours".

  5. Step 5 of 6 · Leads

    Visitors become leads, and a person is one tap away.

    The assistant asks for a name and number with a consent notice, and hands the chat to the business on WhatsApp, by phone or by e-mail, with a reference code so nobody repeats themselves.

    • Contact data is encrypted, and consent follows India's DPDP Act notice rules.
    • A daily digest and an instant notice for hot leads.
    • A monthly value report in rupees, with its formula shown.

  6. Step 6 of 6 · Get paid

    Every answer is metered, and the balance pays for it.

    Each business has a prepaid balance. It tops up online, each answer is charged once, and a statement shows the month. When the balance runs out, visitors get a polite message and a way to reach a person, never an error.

    • Per-question prices, or the AI cost plus your markup.
    • Spending caps, renewal notices and a profit report for you.
    • A free local model for cheap plans: no API bill for those answers.

Four ways in.

A knowledge base has a key. The key can upload, ask and read usage for that knowledge base, and nothing else.

  • REST: every route is in docs/openapi.json.
  • Python and JavaScript: the clients are in clients/, under MIT.
  • Widget: a publishable pk_ key that only chats, only on the sites you list.
  • MCP: cob-rag-mcp gives agents 52 tools and a command-line tool.

Why not LangChain, LlamaIndex or Dify?

LangChain and agent SDKs (OpenAI Agents SDK, Claude Agent SDK, LangGraph) are toolkits for building AI. cob-rag-engine is the finished knowledge platform and chatbot business your agents and your customers use: install it and sell AI assistants the same day.

Say it in four lines
  1. LangChain, LlamaIndex and the agent SDKs give you parts to build with; cob-rag-engine is the finished knowledge platform: customers, keys, documents, fact-checked answers, a website widget and billing, already built and tested.
  2. They are not rivals: your LangChain, LlamaIndex, OpenAI or Claude agent plugs into it over MCP and uses it as its governed knowledge base.
  3. Dify is a full platform too, but it is built for designing apps, and its licence needs written authorization to run it for many customers; cob-rag-engine is built to resell, with plans and billing, Hindi and Hinglish, WhatsApp and DPDP consent, and answers that stay inside the customer's own documents.
  4. So you sell assistants from day one instead of building the platform under them, and if all you need is a one-off prototype, LangChain alone is the right call.

What it does not do yet, and what comes next.

So you can decide before you build on it, not after.

Not in the code yet

  • Release 0.2.0: automated tests, no full live run yetThe engine has run real deployments before. This release passed its automated tests (about 19,000 unit tests, about 400 integration tests and the dashboard's tests), but the newest parts (online payments, WhatsApp answers, the public website and the installer) have not yet had a full live run on a fresh server. That run is next. If something breaks, please open an issue on GitHub.
  • No live takeover inboxYour team cannot chat with a visitor inside the dashboard yet. A visitor who wants a person gets WhatsApp, a call or e-mail.
  • No voice assistantThere is no phone or voice channel.
  • No Drive, Notion or Confluence connectorsUpload files, read a website, or push records through the API.
  • No single sign-onSign-in is e-mail and password, with owner and member roles.
  • Razorpay only, and tested against a simulatorNo Stripe yet. Payments and WhatsApp were tested against simulated Razorpay and Meta servers, not live accounts.
  • One server, no hosted versionDocker Compose on one server is the supported path, and there is no Kubernetes chart. There is no hosted cob-rag-engine: you run it yourself.

Coming next, in this order

  • NextLive chat and a bot teamAn inbox where staff take over a chat, and named specialist bots with a visible handover.
  • PlannedGraphRAG and imagesAnswers that join facts across documents, and diagrams and pictures as searchable content, as optional add-ons.
  • PlannedAgents that do thingsBooking a home collection or checking an order. Agent mode and web search exist in the code but are not in the API yet.
  • LaterData connectorsGoogle Drive, Notion and Confluence, with incremental sync.

On a server

A fresh Ubuntu 22.04 or 24.04, or Debian 12, and a domain that points at it. The requirements page lists the server sizes.

Terminal · on the server
git clone https://github.com/callobuzz/cob-rag-engine.git
sudo bash cob-rag-engine/deploy/install.sh

Add --dry-run to see every step without changing anything.

On your computer

Windows, macOS or Linux with Docker. The wizard asks a few questions, writes the settings with new secrets, and you start the stack.

Terminal · on your computer
git clone https://github.com/callobuzz/cob-rag-engine.git
cd cob-rag-engine
make setup            # or: python scripts/setup.py
docker compose up -d --build
