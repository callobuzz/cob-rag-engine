01What you’ll have running#

cob-rag-engine is a self-hosted knowledge engine. Each business you serve (a customer, called a tenant in the API) gets private knowledge bases: its documents go in, and cited answers come out through a website chat widget, your own app, or an AI agent. You run one Docker Compose stack: the engine API, a background worker, a mailer, a scheduler, a web scraper, the dashboard, and the datastores (PostgreSQL, Redis, Qdrant, MinIO and the embedding container). This guide takes you from a fresh clone to a first customer with a working widget, then covers day-to-day running and what to do when something breaks.

Good to know
Every port is published on 127.0.0.1 only (RAG_BIND_ADDR), so only your own machine can reach the stack. The three web ports are configurable through RAG_APP_HOST_PORT, RAG_SCRAPER_HOST_PORT and RAG_DASHBOARD_HOST_PORT; step 4 shows how the wizard changes them for you. The other ports are fixed in docker-compose.yml.

02Before you start#

2.1Software#

  • Docker with Compose v2: Docker Desktop on Windows or macOS, Docker Engine on Linux. You need the docker compose command (two words), not the old docker-compose.
  • Python 3.10 or newer, only for the setup wizard. The wizard uses the standard library, so there is nothing to pip install and no virtualenv to create.
  • git, to clone the repository.
  • make is optional. make setup is only a shortcut for python scripts/setup.py.

Check what you have:

Terminal
docker --version
docker compose version
python --version
git --version
Tip
If python is not found, install Python 3.10 or newer (on Windows tick “Add python.exe to PATH” in the installer). On macOS and Linux the command is often python3; make setup uses python when it works and python3 otherwise, so it needs no change; without make use the python3 scripts/setup.py form.

2.2Your machine#

  • Memory: 4 GB of RAM or more for Docker. The default stack measured 2.1 GB on CPU with 270,000 chunks indexed. Turning on the local re-ranker on CPU adds about 2.3 GB.
  • Disk: the repository does not state a figure. The first start builds three images and downloads several more plus an embedding model, so keep several GB free. Ten GB is a comfortable margin; that number is a rule of thumb, not something we measured.
  • An NVIDIA GPU is optional. It only makes the local models faster (the embedding model and a local re-ranker), not better. Hosted APIs and LLM re-ranking run at the provider either way. To see whether Docker can use your GPU, run this (it is the same check the wizard suggests; it downloads a small image the first time):
Terminal
docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi

If it prints a table with your GPU, Docker can use it. If it fails, answer “no” to the GPU question later; everything works on the CPU.

You chose no GPU, so skip this check: everything local runs on the CPU. If you get one later, re-run the wizard and answer yes.

No NVIDIA GPU on a Mac
Docker on a Mac cannot use an NVIDIA GPU. Choose “No” in your setup; everything runs on the CPU.

2.3An AI model key#

Answers are written by a language model, so you need one provider key: OpenRouter (one key, hundreds of models), OpenAI, Anthropic (Claude), Google Gemini, or a local Ollama with no key at all. You can skip this during setup: uploading and searching work without a key, and only answering needs one. The key is stored in your local .env file and nowhere else.

You said you will add one, so have the key ready before step 4: the wizard asks for it (hidden as you type).

You chose to skip it for now. Do step 4 without a key and add it afterwards; Ask in the playground shows how.

4.2Quick or full#

  • Quick (the default, recommended): the GPU question once, then your e-mail, the AI model, how to send e-mail, and the re-ranker. Start here.
  • Full: also asks about the environment (development or production), where embeddings run, where uploaded files are stored, the web addresses and host ports, the network bind address, and the optional services (audio transcription, Langfuse) and the answer-quality evaluation add-on. 4.3What each answer means#

GPU
“Do you have an NVIDIA GPU that Docker can use?” It is asked once, first, and yes / no / not sure (not sure is treated as no and prints the check from step 2). The answer decides three things: whether the start command includes the GPU overlay, whether the bundled embedding container (TEI) uses its CUDA image, and where a local re-ranker runs. --gpu yes or --gpu no answers it up front.
Super-admin e-mail
The account you sign in to the dashboard with, for example admin@yourcompany.in. It gets a link to set its password. It must be a real address: names that never receive mail (.local, .test, .example, .localhost, .invalid) are accepted only when the environment is development (RAG_ENV=dev) and refused in production, and the wizard asks again. Press Enter to skip; you then sign in with the admin API key instead (step 6).
AI model
Pick a provider, the model that writes answers, and a fast model; the wizard suggests both per provider (answers / fast: OpenRouter openai/gpt-oss-120b / openai/gpt-6-luna, OpenAI gpt-6.1-sol / gpt-4.1-mini, Anthropic claude-sonnet-5-5 / claude-haiku-4-5, Gemini gemini-3.8-flash / gemini-3.5-flash-lite, Ollama llama3.1 / llama3.2). The fast model is a small, quick model from the same provider that rewrites the search question before it is searched (RAG_LLM_FAST_MODEL); Use a small non-thinking model here: it labels every message and suggests follow-ups; a thinking model makes replies slow. Budget option. On OpenRouter the wizard shows two fast models as a numbered choice and defaults to the first: openai/gpt-6-luna (recommended, 98.9% accurate, about ₹13.6 per 1,000 messages) and google/gemma-4-26b-a4b-it (64% cheaper, about ₹4.9 per 1,000, 97.7% accurate); the numbers come from the fast-model benchmark. Thinking is one setting for every model: RAG_LLM_THINKING for answers and RAG_LLM_FAST_THINKING (default off) for the fast model, each off, minimal, low, medium, high or provider-default, and per knowledge base under Model & keys. Off is fastest and cheapest; turn it on only for hard questions. A model that cannot stop thinking (gpt-oss, Gemini 3 Flash) runs at its lowest setting, and every answer says what it ran at. A model per language: on OpenRouter the wizard also asks whether Hindi and Hinglish replies should use their own model (default yes, google/gemma-4-31b-it, written to RAG_LLM_LANGUAGE_MODELS). The assistant notices the language of each message, so Hindi (Devanagari) and Hinglish (Hindi in English letters) are answered by Gemma 4 31B, which had the best Hindi tone and the fastest first word in the answer benchmark, while English keeps the main model (openai/gpt-oss-120b by default, at thinking low). The chosen model answers at its lowest thinking setting, wherever the assistant answers (the plain query, widget and conversation endpoints included). Change it per knowledge base under Model & keys → Model per language (the language switch can follow the engine, name a model per language, or be off); the engine page shows the engine's setting. Routing only applies on the engine's own provider: a knowledge base with a key for another company keeps its model unless you name models for it. The engine skips the rewrite altogether for greetings and questions of three words or fewer. Then paste the key, which is hidden. For Ollama it asks for the address, http://host.docker.internal:11434 by default, because from inside Docker your machine is host.docker.internal. Choose “Skip for now” to add the key later as RAG_LLM_API_KEY in .env.
E-mail sending
E-mail carries sign-up codes, password resets and invitations. Skip is fine on your own machine: in development the codes and links go to the logs (step 7 shows where). Gmail or Google Workspace needs an app password (2-step verification on, then create one). Another SMTP server asks for host (for example smtp.zoho.in), port, connection security, login and a sender such as Shree Labs <no-reply@shree-labs.in>.
Re-ranker
A second pass that re-reads the top search results and reorders them. Off is the safe start. In the project’s benchmarks the local model helped on question-and-answer data (the chatbot case) and hurt on other kinds of search; re-ranking through your LLM has not been measured yet. The options follow your GPU answer. With a GPU: off, local on the GPU (about 0.4 s a question), or through your LLM. Without one: off, through your LLM (small cost per question), or local on the CPU (free but about 10 s a question and 2.3 GB of RAM). You can change it per knowledge base later in the dashboard (Knowledge base, then Retrieval).
Embeddings
Quick mode does not ask. It uses the bundled TEI container with the model BAAI/bge-base-en-v1.5, on your GPU if you said yes and on the CPU otherwise. Full mode lets you choose: TEI on CPU, TEI on GPU (offered only if you said yes), inside the engine (BGE-M3), or a hosted API (OpenAI, Cohere, Voyage, Mistral, Gemini or Jina). Changing the embedding model for a knowledge base that already has documents needs a re-embed.
Warning
On Docker Desktop for Windows, TEI’s CUDA image cannot see the GPU (the README says so). If you are on Windows with a GPU, quick mode already handles this: it runs the engine’s own embedding model on the GPU instead of TEI.

Re-running is safe. 5.2The first start takes a while#

The first run builds the engine, scraper and dashboard images and pulls the datastore images, then downloads the embedding model. The compose file gives the embedding container a 120 second grace period before it even checks its health, then 30 checks ten seconds apart, because the model download is the slow part. Models are kept in a Docker volume, so later starts are quick. You can watch it with docker compose logs -f tei. There is no embedding container to wait for here: the engine loads its own embedding model (BGE-M3), which is downloaded too. Embeddings come from the hosted API you chose, so there is no embedding model to download. The local re-ranker model downloads as well.

5.3Wait until it is healthy#

Terminal
docker compose ps

Run it again every minute or so until the app service says healthy. When it does, the engine’s health URL answers in your browser. The engine runs its database migrations by itself as it starts, so there is nothing to migrate by hand. If something stays unhealthy or keeps restarting, jump to reading the logs.

5.4Embedding model#

The default is BAAI/bge-m3 (1024-d, multilingual including Hindi and Hinglish), served by the bundled TEI container, roughly 2.3 GB of weights in memory on CPU (an estimate, not measured). A fresh install needs nothing.

An existing install keeps the model in its own .env (RAG_EMBEDDING_MODEL, RAG_EMBEDDING_DIMENSIONS, RAG_TEI_MODEL_ID), so upgrading the engine changes nothing. To switch, set those to BAAI/bge-m3, 1024 and BAAI/bge-m3 and restart: the daily drift check queues one re-embed migration per knowledge base (GET /api/v1/migrations). Start each with POST /api/v1/migrations/{id}/approve, or all of them with POST /api/v1/admin/migrations/approve-all. It builds the new index beside the old one and swaps once verified, so answers keep working; POST .../rollback undoes it.

Not this
python -m callobuzz_rag.retrieval.reindex --dense is not the way to switch models: it re-embeds with the same model.

10Set up billing in 5 minutes#

With no price on a plan, nothing is charged and nobody is paused, so you can ignore this section and your customers are limited by their plan only. 10.1Pick a recipe#

Open Billing, then Pricing, choose a plan and press Edit pricing. The three common set-ups:

  1. Subscription, own key free. Choose Postpaid with a credit limit at least as large as the fee, so a customer is never paused for the fee itself. Customers who bring their own AI key pay you only the fee.
  2. Pay per question. Choose Prepaid, set A price per question (for example ₹2), and set the Alerts (20, 5 and 0 percent by default). A customer tops up, each answer takes its price from the balance, and answers pause politely at zero.
  3. Real AI cost plus a markup. Choose AI cost plus a markup and enter the markup percentage (25 means 25 percent on top). Each answer is charged what the AI really cost you, converted to rupees at the fixed rate RAG_USD_INR_RATE. The rate is written on the charge, so a charge can always be explained later, even after you change the rate. A call with no known price is charged ₹0 and flagged “price unknown” on the statement. Customers never see the markup.

Press Save pricing. Every save is a new version with a history, and it applies to the next answer. For one customer who deserves a different deal, open their Billing tab, turn on Custom for just the fields you want to change, and press Save terms. 10.2Top-ups, refunds and add-ons#

Payments are recorded by hand for now. When a customer pays you (or asks through Request top-up on their Plan & billing page, which e-mails you), open their Billing tab and press Add a transaction:

  • Top-up adds money to the balance. A large amount must be typed a second time to confirm it.
  • Refund takes money back out. It is limited to what the customer actually paid and still has, and needs a private note.
  • Adjustment corrects a mistake, up or down, with a private note. Nothing in the transaction list is ever edited or deleted; every correction is a new line.

Add-ons are extras you sell: credit packs (money plus an optional bonus), extra limits (more knowledge bases, documents or widget keys) and extra questions for the month. Create them under Billing, Add-ons, then press Apply an add-on on the customer’s tab and say how it was paid: outside the engine, free, or taken from their balance. Pressing a button twice never applies it twice.

10.3What visitors see when a balance runs out#

A prepaid customer pauses when what they can still spend reaches zero (less their grace amount); a postpaid one when they owe their credit limit. The owner is e-mailed at each alert level and again when answers pause, and so are you. Visitors never see the word billing: the assistant still greets them and answers the fixed topics, and any other question gets the knowledge base’s message when answers are paused with its contact card, so nobody is lost. The pause costs you nothing, because no AI model is called. Adding money lifts it within a minute. Pause override on a customer lets you force a pause or never pause.

10.4Statements, the P&L and provider balances#

Every customer gets a statement for each calendar month: opening balance, subscription, usage by knowledge base, model and source, top-ups and the closing balance, which always adds up to the transactions to the last paisa. Customers open it themselves (View, CSV, Download PDF); it never shows your markup or AI cost. Billing, P&L compares what each customer was billed and paid with what your AI key cost you (an estimate), month by month, with the margin. On Costs, Provider balances shows what OpenRouter, OpenAI, Anthropic and any manual provider have left so you know when to top up your own keys. Every night the engine checks that each balance equals its transactions and that every answer was charged once; Books check shows the result and Check now runs it on demand.

  2. Step 1, your website. The owner types shreedental.in, names the assistant (for example “Shree Dental Assistant”), chooses its picture, and presses Continue. The knowledge base, the assistant, the website code and the reading of the website are all set up in one go.
  3. Step 2, add it to your website. The owner copies the code, or presses Send to my developer. A light turns green with Connected the moment the assistant loads on the website.

11.3Keeping the website knowledge fresh#

A learned page is checked on a schedule the owner picks (every day by default). A page is read again only when it has changed, so frequent checks cost nothing extra. Three things make it faster than the schedule:

  • The update link. In Knowledge, Update instantly when you publish makes a link the website can call when it publishes a page. Developers on WordPress or any other system can call it from a plugin or a hook. The link is shown once.
  • The widget. The widget on the website notices when a page’s text changed and asks the engine to check that page. It sends only a short code, never the text and never anything a visitor typed.
  • Removed pages. A page that is gone from the website is forgotten after two checks an hour apart. A temporary outage changes nothing.

11.4The light never turns green#

Symptom
Step 2 keeps showing Waiting for your website.
Why
The code is not on the page that was opened, the website was not published after pasting it, or the site is open in an editor preview.
Fix
Paste the code before the closing </body>, publish the website, then open the live page once. After 15 minutes the setup stops checking and the owner can finish later from Home.

11.5www and the plain address do not match#

Symptom
The light says the assistant loaded on www.shreedental.in but the owner typed shreedental.in (or the other way round).
Why
Visitors reached the website by another address than the one allowed.
Fix
Both forms are allowed at setup. If another address appears, press Allow next to it and reload the website.

11.6Google Sites#

Symptom
The assistant loads, but the address shown is a Google address.
Why
Google Sites shows the chat inside a box served from a Google domain.
Fix
Allow the address the setup shows. The pages of the Google Site itself are read from the owner’s own web address when it has one.

11.7robots.txt blocks the bot#

Symptom
Every page shows Asked search engines not to read it, or the website is marked as unreadable.
Why
The website’s robots.txt or page settings ask programs not to read it. The engine obeys them.
Fix
Ask whoever looks after the website to allow reading, or add the owner’s important pages to the assistant as articles in Knowledge.

11.8A website that needs a browser#

Symptom
Pages show Needs a browser to read and few or no pages are learned.
Why
The text is built only inside a browser (a single-page app), so a plain read finds almost nothing.
Fix
If you run the web scraper with browser reading switched on, these pages are read through it. Otherwise the owner can write the key pages as articles and question-and-answer entries.

12Tear down and reset#

12.1down versus down -v#

docker compose down stops the stack and keeps your data. docker compose down -v also deletes the volumes.

This deletes data
docker compose down -v permanently deletes the database, vector store, uploaded files, Redis data and model cache: every customer, knowledge base, document and account on this install. There is no undo. Use it only when you want to start from nothing. (make clean runs the same down -v and also removes Python cache folders.)
Terminal
docker compose down -v

12.2Remove the images too#

The images take disk space. This stops the stack, deletes the volumes and removes the images Compose used (Docker skips any image another project still uses):

Terminal
docker compose down -v --rmi all

12.3Start completely fresh#

  1. Delete the data: docker compose down -v.
  2. Move the old settings aside. The wizard keeps the values it finds, so to get brand-new secrets the file has to be gone:
Git Bash
mv .env .env.old
PowerShell
Rename-Item .env .env.old
Terminal
mv .env .env.old

Then run the wizard again (step 4) and start the stack (step 5).

Warning
Delete the volumes whenever you replace .env. PostgreSQL only reads its password when its volume is first created, so new secrets with the old volume leave the app unable to sign in to the database. To reset the data but keep your settings, leave .env in place.

13Troubleshooting#

Each item reads symptom, why it happens, fix. The ones that match your setup come first. Start with docker compose ps and docker compose logs <service>; they answer most questions.

13.1Port already in use#

Symptom
docker compose up fails with a message like “port is already allocated” or “address already in use”.
Why
Another program on your machine already uses one of the ports (8000, 8001, 8090, or a datastore port such as 5433 or 6380).
Fix
Find it, then free it or move the stack. To see who holds a port (8000 here):
Git Bash
netstat -ano | findstr :8000
PowerShell
netstat -ano | findstr :8000
Terminal
lsof -i :8000
To move the three web ports, re-run the wizard with --full (it asks for the host ports and updates the matching addresses and allowed origins), or pass one directly:
Terminal
python scripts/setup.py --quick --yes --gpu no --set "RAG_APP_HOST_PORT=8100"
Then run the start command again. The datastore, MinIO, TEI and Qdrant ports are fixed in docker-compose.yml; stop whatever uses them instead.

13.2Docker Desktop is not running#

Symptom
Every docker command fails with “Cannot connect to the Docker daemon” or, on Windows, a pipe error such as “The system cannot find the file specified”.
Why
The Docker engine is not started. Docker Desktop has to be open (or the Docker service running on Linux) before any compose command works.
Fix
Start Docker Desktop and wait until it says the engine is running.Start the service with sudo systemctl start docker. Check with docker info, then run the start command again.

13.3Containers are unhealthy or restarting#

Symptom
docker compose ps shows unhealthy, Restarting or Exited for a service.
Why
Something the service needs is missing or wrong. The last lines of its log almost always say what.
Fix
Read the log of that service, newest lines last:
Terminal
docker compose logs --tail=100 app
Replace app with the service name. Causes the wizard itself warns about: RAG_SMTP_HOST set but RAG_SMTP_FROM empty (the engine will not start); RAG_ENV=prod with RAG_EMAIL_PROVIDER=log (refused); RAG_EMBEDDING_PROVIDER=tei without tei in COMPOSE_PROFILES (ingestion fails). A line such as “set RAG_DB_PASSWORD in .env” means a required secret is empty: re-run the wizard. A failed migration shows “ERROR: Alembic migration failed!” in the app log. After fixing .env run docker compose up -d.

13.4The first start is very slow#

Symptom
docker compose ps shows tei as starting for minutes, and the app does not become healthy.
Why
The embedding container downloads its model (BAAI/bge-base-en-v1.5) on first start, and the images are being built. This is normal.
Fix
Wait, and watch docker compose logs -f tei. The compose file allows TEI 120 seconds before the first health check and then 30 checks ten seconds apart. The download is cached in a Docker volume, so the next start is fast. If you chose a local re-ranker or in-engine embeddings, those models download too.

13.5The GPU is not used#

Symptom
Embeddings or the re-ranker run slowly, the TEI log does not say it is starting the model on Cuda, or Compose refuses to start a service with “could not select device driver nvidia”.
Why
Compose refuses to start a service that reserves a GPU the host does not have, which is why the GPU overlay is never the default. The TEI container also needs the CUDA image, not the CPU one. On Docker Desktop for Windows, TEI’s CUDA image cannot see the GPU.
Fix
Run the GPU check from step 2. If it fails, answer “no” (python scripts/setup.py --gpu no) and use the plain start command. If it works, answer yes and use the GPU start command. On Windows, quick mode picks the engine’s own embeddings for you, which use your GPU without TEI. For TEI on Linux with a specific card you can set RAG_TEI_IMAGE to the tag for its generation: turing-1.9, 86-1.9 (Ampere), 89-1.9 (Ada), hopper-1.9, 120-1.9 (Blackwell) or the portable cuda-1.9, all under ghcr.io/huggingface/text-embeddings-inference. The local re-ranker alone needs about 2.3 GB of GPU memory.

13.6localhost does not work on Windows#

Symptom
http://localhost:8090 resets or never loads, but the containers are healthy.
Why
On Windows with Docker Desktop, localhost resolves to the IPv6 address ::1 first, and Docker Desktop resets that connection. It looks exactly like the service being down.
Fix
Use http://127.0.0.1:8090 (and 127.0.0.1 in every address you put in .env).

13.7The dashboard cannot reach the engine#

Symptom
The dashboard loads but shows a network or connection error, or every call fails in the browser.
Why
Your browser calls the engine and the scraper directly. Two settings must match the address you actually use: RAG_DASHBOARD_ENGINE_URL and RAG_DASHBOARD_SCRAPER_URL (where the browser reaches them), and RAG_CORS_ORIGINS (which must list the dashboard’s own origin; the scraper has SCRAPER_CORS_ORIGINS). They break when you change a port, open the dashboard from another address, or put the stack behind a domain. The dashboard’s Content-Security-Policy only allows calls to the two configured addresses.
Fix
First check the engine itself: http://127.0.0.1:8000/api/v1/health should answer. Then run python scripts/setup.py --full and set the “Web addresses” (it merges the dashboard’s origin into both CORS lists), and recreate the services with docker compose up -d. For a live deployment use your public https addresses and follow the deploy guide.

13.8There is no set-password link#

Symptom
You search the logs and find no “ONE-TIME SET-PASSWORD” block, or no e-mail arrived.
Why
The link is only created when RAG_SUPERADMIN_EMAIL is set (otherwise the log says “No RAG_SUPERADMIN_EMAIL; skipping”), and the account needs RAG_SESSION_SECRET, which the wizard generates. With SMTP the link is e-mailed, not printed. Old log lines may also have rotated away.
Fix
Re-run the wizard and enter the e-mail (or --set "RAG_SUPERADMIN_EMAIL=admin@yourcompany.in"), then restart the app with docker compose up -d app. To issue a new link and print it on screen right now:
Terminal
docker compose exec app python -m callobuzz_rag.accounts.bootstrap --resend --print-link
If your password is already set, --resend issues a fresh code anyway.

13.9Sign-up codes do not arrive#

Symptom
A customer signs up but no 6-digit code shows up in their inbox.
Why
You skipped SMTP in the wizard, so nothing is sent: in development (RAG_ENV=dev) every message is written to the mailer’s log instead.The mail server may be refusing the message. Gmail needs an app password, not your normal password, and the message may have landed in spam. In production (RAG_ENV=prod) with no SMTP, e-mail is disabled and sign-up is unavailable.
Fix
Read the code from the log:
Git Bash
docker compose logs mailer | grep -A12 "DEV EMAIL"
PowerShell
docker compose logs mailer | Select-String -Context 0,12 "DEV EMAIL"
Terminal
docker compose logs mailer | grep -A12 "DEV EMAIL"
Check the mailer’s log (docker compose logs mailer) for errors, and use With SMTP set up you would check the same log for errors, and you could use Email (SMTP) in the operator dashboard to check the configuration and send yourself a test. Temporary failures are retried after 15, 30, 60, 120 and 240 seconds, and a message whose code would already have expired is dropped (codes last 10 minutes), so ask for a new code.

13.10“Too many attempts” or a sign-in lockout#

Symptom
The dashboard says “Too many attempts. Try again in …” or “Too many tries. Login is paused for …”.
Why
The engine rate-limits the account routes. Sign-in allows 10 tries per e-mail per 15 minutes and 30 per address per 5 minutes. From the fifth wrong password in 15 minutes the e-mail is locked for 1 minute, doubling each further failure up to 15 minutes, and the lock refuses even the right password. Sign-up allows 5 per hour from one address and 3 per hour for one e-mail. The limits live in Redis, and if Redis is down the engine refuses rather than running unlimited (“Sign-in is briefly unavailable”).
Fix
Wait for the time the message gives. A correct sign-in, or finishing a password reset, clears the failure count and the lock. If you see “briefly unavailable”, check docker compose ps redis.

13.11“Workspace not active”#

Symptom
A customer sees “We’ll activate your workspace soon” or “<name> is paused”, or their key gets a 403 workspace_not_active.
Why
The workspace is pending (approval mode, not activated yet) or suspended. Their people can still sign in and see the status page; keys, widgets and agents are refused, and widget visitors see “This assistant is not available right now.”
Fix
As operator, open Customers. Choose Activate on the Pending tab, or Reactivate on the Suspended tab. It takes effect on the next request and nothing was deleted.

13.12A plan limit message#

Symptom
“Monthly question limit reached (412 of 1,000). It resets on …”, or “Your plan allows N knowledge bases / documents / website widget keys.”
Why
The customer’s plan has a cap and they reached it. The month is the calendar month in UTC. Searches that only retrieve passages are not counted, and cached answers do not count. The admin key and super admin are never capped.
Fix
Move the customer to a bigger plan (Customers, then Change plan) or edit the plan under Plans. Lowering a limit never deletes anything; it only blocks new additions. At the question cap, widget visitors see a polite “not available” message and nothing about the plan.

13.13An upload is refused as too large#

Symptom
The upload is refused with “File too large” (HTTP 413, code upload_too_large), or it is accepted and the job later fails with “The document holds N tokens of text; the limit is M” (code document_too_large).
Why
There are two limits. The file itself may be at most RAG_MAX_UPLOAD_BYTES (50 MB by default). And the text inside it, counted after the engine has read the file, may be at most RAG_MAX_DOCUMENT_TOKENS (500,000 tokens by default), so a large scan with little text is fine and a small file with a great deal of text may not be. A plan can set lower limits for one customer, and the dashboard shows the limits that apply to you when you add content.
Fix
Split the document into smaller files, or export its text and import it as records (Add content, then Records import, or POST /api/v1/ingest/records), which takes up to 1,000 records per request and up to 200,000 characters of text in each. To allow more, raise the two settings in .env and restart, or raise the customer’s plan limits.

13.14Answers are slow#

Symptom
The playground or widget takes many seconds to answer.
Why
Most of the time is the language model: a large model, a slow provider, or Ollama running on a CPU. The second common cause is the local re-ranker on a CPU, which the wizard measured at about 10 s a question.
Fix
Choose a faster model (RAG_LLM_MODEL, or per knowledge base in the dashboard). Set a small, quick fast model from the same provider (RAG_LLM_FAST_MODEL): with none, a thinking model rewrites every search question itself, at RAG_LLM_FAST_THINKING (off, or the model’s lowest setting). If your model thinks before it answers, switch Thinking off (RAG_LLM_THINKING=off, or per knowledge base under Model & keys in the dashboard): off is fastest and cheapest, high is more careful. The older RAG_LLM_REASONING_EFFORT still works (none means off). Turn the re-ranker off, or use it on a GPU or through your LLM (the Standard and Premium presets already leave it off on a machine without a GPU unless you switch it on for the whole engine): re-run the wizard and answer the re-ranker question, or change it under the knowledge base’s Retrieval settings.

13.15Answers fail: no AI model key#

Symptom
The playground or the widget cannot answer, while uploading and searching work.
Why
You skipped the AI model in the wizard. Answers are written by a language model, so they need a key; only uploading and searching work without one.
Fix
Set RAG_LLM_API_KEY in .env (the default provider is OpenRouter; for another provider also set RAG_LLM_PROVIDER and RAG_LLM_MODEL, or re-run the wizard and pick one), then recreate the services:
Terminal
docker compose up -d
An owner can also give one knowledge base its own model and key in the dashboard.

13.16I forgot the admin password#

Symptom
You cannot sign in to the dashboard as the super admin.
Why
Passwords are stored as hashes, so nobody can read them back, but there are two ways in.
Fix
Use Forgot password? on the sign-in page. It sends a reset code to your e-mail (with no SMTP, find it in the mailer log as in the sign-up item aboveit arrives by e-mail). Or sign in with the admin key through Use an API key instead (RAG_ADMIN_API_KEY in .env). Or issue a new set-password link with the bootstrap --resend --print-link command from the “no set-password link” item. Finishing a reset also clears any sign-in lockout.

13.17Where is the admin API key?#

Symptom
You need the admin key for the API, the MCP server, or the dashboard’s key sign-in, and you do not remember it.
Why
The wizard generated it and, like every secret, never printed it.
Fix
It is RAG_ADMIN_API_KEY in the .env file in the repository root. Print just that line with the command under First login, the admin key. Send it in an X-API-Key header. Keep it private: it can do everything on the engine.

13.18Back up RAG_ENCRYPTION_KEY#

Symptom
You are moving to a new machine, rebuilding, or worried about losing .env.
Why
RAG_ENCRYPTION_KEY encrypts the LLM keys your customers store in their knowledge bases. Without it those stored keys cannot be read, and every customer would have to paste theirs again. It is generated once and never printed.
Fix
Copy it into a password manager now, apart from the repository. The wizard’s .env.backup-* files and your .env hold all your secrets, so store them as carefully as the key. The engine can rotate the key, and python -m callobuzz_rag.core.reencrypt rewrites stored tokens under the new primary key; see the README’s Operations section.

13.19A file fails: no readable text#

Symptom
A file is uploaded but its job fails with “We couldn’t find readable text in this file. If it’s a scanned PDF, enable OCR or upload a text version.” (code no_text_found). Nothing is added to the knowledge base.
Why
The engine read the file and found no text in it. The usual cause is a scanned PDF or a photo of a page while OCR (reading text from images) is switched off, or a file that is empty or holds only pictures.
Fix
For a scan, set RAG_OCR_ENGINE to rapidocr (the default) or tesseract in .env and restart, then upload it again. For Hindi or another Indian language see 12.20. Otherwise export the text and upload that, or import it as records. A file you were replacing stays exactly as it was.

13.20A scanned Hindi document comes out garbled or empty#

Symptom
A scanned PDF or photo in Hindi (or Marathi, Tamil, Telugu...) is ingested, but its text is missing words, jumbled or Latin-only.
Why
OCR reads English unless you tell it the language, and the default engine (rapidocr) reads Devanagari unreliably: on our test page it recovered about half of the text, while paddleocr recovered 99%. The engine logs a warning at start-up when RAG_OCR_LANGS names an Indian language and RAG_OCR_ENGINE is rapidocr.
Fix
Set RAG_OCR_LANGS=hi,en and RAG_OCR_ENGINE=paddleocr in .env (the first non-English language picks the model; it reads the English words too). PaddleOCR is an optional extra: build the image with docker compose build --build-arg INSTALL_OCR_PADDLE=true, or run pip install -e ".[ocr-paddle]" when you run natively. Restart, then upload the file again. Prefer Tesseract? Set RAG_OCR_ENGINE=tesseract; the image already has the Hindi data (tesseract-ocr-hin), and other languages need their own tesseract-ocr-<code> package added to the Dockerfile. Codes: en, hi, mr, ne, sa, ta, te, kn (paddleocr and rapidocr), plus bn, gu, ml, pa, or, as, ur (tesseract only).
